# هشامكو — نظام إدارة الأعمال المتكامل

تطبيق ويب حقيقي (Node.js + PostgreSQL) يبني على النموذج الأولي `erp-shell.html` والمواصفة
التقنية المرفقة. هذه المرحلة تنقل المحرك المحاسبي ونقاط البيع من التخزين المحلي
(`localStorage`) إلى خادم API حقيقي وقاعدة بيانات علائقية حقيقية، وتضيف **وحدة المخزون**
كأول وحدة جديدة حسب خارطة الطريق في القسم 10 من المواصفة.

## البنية

```
backend/    خادم API — Express + PostgreSQL (pg)
frontend/   واجهة الويب — HTML/CSS/JS عادي (fetch إلى الـ API)، بنفس هوية النموذج الأولي
```

الخادم يخدم الواجهة أيضاً كملفات ثابتة، فالتطبيق كله يعمل من نفس المنفذ.

> **لتجربة نقاط البيع فعلياً في مطعم بأسرع طريقة (بدون تثبيت Node.js أو PostgreSQL يدوياً)**،
> راجع [`دليل_التشغيل_السريع.md`](./دليل_التشغيل_السريع.md) — تشغيل بأمر واحد عبر Docker.

## ما تم بناؤه في هذه المرحلة

- **محرك محاسبي حقيقي**: شجرة حسابات، عناصر تحليلية (الدفاتر المساعدة)، قيود يومية بقيد
  مزدوج مُتحقَّق منه على مستوى قاعدة البيانات (توازن المدين/الدائن + إلزامية العنصر التحليلي
  لأي حساب إجمالي)، دفتر أستاذ، ميزان مراجعة، والقوائم المالية الأربع.
- **نقاط البيع**: مرتبطة الآن بكتالوج أصناف حقيقي ومستودعات حقيقية، الفاتورة تُنشئ تلقائياً
  قيد إيراد **وقيد تكلفة بضاعة مباعة (COGS)** بناءً على التكلفة المتوسطة المرجّحة الفعلية.
- **وحدة المخزون (الجديدة)**:
  - مستودعات متعددة — تُبنى كعناصر تحليلية تحت حساب "1200 المخزون"، فتُطبَّق عليها تلقائياً
    نفس آلية فحص السلامة الموجودة أصلاً (مجموع أرصدة المستودعات = رصيد حساب المخزون الإجمالي).
  - أصناف بخمسة أنواع (خام / نصف مصنّع / تام / تعبئة / مستهلكات) مع تكلفة متوسط مرجّح متحركة.
  - استلام وتسوية مخزون يدوية (لحين بناء وحدة المشتريات).
  - تحويل بين المستودعات بقيمة التكلفة، يُسجَّل بقيد محاسبي بين عنصرين تحليليين لنفس الحساب.
  - جرد فعلي (مسودة → إدخال الكميات الفعلية → ترحيل يُسجّل فروقات الجرد تلقائياً).
  - وصفات تصنيع (BOM) — تعريف المكوّنات فقط؛ الاستهلاك الفعلي في أوامر الإنتاج يأتي مع
    وحدة الإنتاج (البند التالي في خارطة الطريق).

## المتطلبات

- Node.js 18+
- PostgreSQL 14+

## الإعداد المحلي

```bash
# 1) قاعدة البيانات
sudo -u postgres psql -c "CREATE ROLE erp_app LOGIN PASSWORD 'erp_app_pw';"
sudo -u postgres psql -c "CREATE DATABASE erp OWNER erp_app;"

# 2) الخادم
cd backend
cp .env.example .env   # عدّل القيم عند الحاجة (خصوصاً JWT_SECRET في الإنتاج)
npm install
npm run migrate        # ينشئ الجداول ويزرع شجرة الحسابات الافتراضية
npm run seed            # ينشئ مستخدم مدير — admin@example.com / ChangeMe123!
npm start                # يشغّل API + الواجهة على http://localhost:4000
```

افتح `http://localhost:4000` وسجّل الدخول بالمستخدم الذي أنشأه `npm run seed`.

لتخصيص بيانات المدير عند البذر:

```bash
SEED_ADMIN_EMAIL=you@company.com SEED_ADMIN_PASSWORD='StrongPass!' npm run seed
```

## ملاحظات معمارية

- **الصلاحيات**: هذه المرحلة تضيف مصادقة JWT بسيطة (مستخدم واحد بدور admin) فقط لتفعيل
  الوصول متعدد المستخدمين الآمن للخادم؛ طبقات الصلاحيات الأربع الموثقة في القسم 7 من
  المواصفة (شاشات/عمليات/مدخلات/تقارير) لم تُبنَ بعد وتحتاج وحدة صلاحيات مستقلة.
- **التكلفة**: تُحتسب بطريقة المتوسط المرجّح المتحرك لكل صنف داخل كل مستودع. طريقة FIFO
  المذكورة في المواصفة كبديل لم تُبنَ في هذه المرحلة.
- **حسابان جديدان** أُضيفا لشجرة الحسابات لدعم المخزون قبل وجود وحدة مشتريات:
  `3900` رصيد افتتاحي (لتحميل الأرصدة الافتتاحية للمخزون)، و `5900` فروقات وتسويات المخزون
  (لتسويات الجرد والتسويات اليدوية).
- **البيانات القديمة**: هذا بناء جديد على قاعدة بيانات حقيقية، فلا يوجد استيراد تلقائي من
  نسخ `localStorage` الاحتياطية للنموذج الأولي.

## الخطوة التالية حسب خارطة الطريق

وحدة **الإنتاج**: أوامر إنتاج تستهلك وصفات BOM المعرَّفة هنا فعلياً من المخزون وتُنتج
صنفاً تاماً بتكلفة فعلية وفق IAS 2 (القسم 6 من المواصفة).
